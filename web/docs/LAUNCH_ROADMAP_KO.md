# Voice With AI 출시 준비 로드맵

## 이 문서의 목적

처음 유료 서비스를 출시할 때는 화면을 더 만드는 일보다 **결제 가능한 기반, 개인정보 보호, 안정적인 운영**을 먼저 갖추는 편이 안전합니다. 이 문서는 Voice With AI를 한국어 베타에서 유료 정식 서비스로 옮기기 위한 우선순서입니다.

> `robots.tst`가 아니라 `robots.txt`입니다. 다만 `robots.txt`는 예의 바른 검색 로봇에게만 안내하는 파일이며, 악의적인 크롤링을 막는 보안 장치는 아닙니다.

## 우선순위 기준

| 구분 | 의미 | 출시 전 필요 여부 |
| --- | --- | --- |
| P0 | 없으면 유료 출시를 하면 안 되는 항목 | 필수 |
| P1 | 출시 직후 운영 안정성과 고객 경험에 직접 영향 | 강력 권장 |
| P2 | 서비스가 안정된 뒤 확장하는 항목 | 이후 진행 |

# 권장 진행 순서

## 0. 출시 기준 먼저 합의하기 — P0

아래 네 가지를 한 문서에 확정합니다.

- 누구를 위한 서비스인지: Discord에서 AI 캐릭터와 텍스트·음성으로 대화하려는 사용자
- 첫 출시 범위: 셀린 1명, 한국어, 무료/유료 플랜, Discord 연동, 음성 동의
- 유료 출시 기준: 결제, 계정 삭제, Discord 연동, 음성 동의 조회, 장애 대응이 모두 테스트됨
- 담당자: 결제·법무·배포·봇·고객 문의를 누가 책임지는지

이 기준이 없으면 기능은 계속 늘어나는데, 실제 결제와 운영에서 필요한 일이 빠지기 쉽습니다.

## 1. 이름·도메인·기본 브랜드 확정 — P0

### 해야 할 일

- 서비스 표기: **Voice With AI**로 통일합니다.
- 회사 표기: **김강.studio** 사용 범위와 법적 사업자명 표기를 구분합니다.
- 도메인 구매: 짧고 오타가 적은 주 도메인 1개와, 필요하면 오타 방지용 보조 도메인을 확보합니다.
- `www` 포함 여부, 공식 이메일 주소(예: `support@...`)도 함께 정합니다.
- 로고는 헤더, 파비콘, Open Graph 공유 이미지, Discord 봇 프로필에 필요한 크기별 파일로 준비합니다.

### 왜 먼저 하나요?

도메인은 Google/Discord 로그인 리디렉션 주소, 쿠키, PG 심사, 약관·개인정보처리방침, 고객지원 이메일에 모두 들어갑니다. 출시 직전에 바꾸면 재설정할 일이 많습니다.

## 2. 사업자·법무·고지 기본 세트 만들기 — P0

### 해야 할 일

1. 사업자등록 준비 및 업종·종목을 세무 전문가와 확인합니다.
2. 통신판매업 신고 대상인지 확인합니다.
3. 다음 문서를 웹사이트에서 쉽게 볼 수 있게 준비합니다.
   - 서비스 이용약관
   - 개인정보처리방침
   - 음성 데이터 처리 정책 및 동의 문구
   - 유료 구독, 청약철회·환불·해지 정책
   - 회원 탈퇴 및 보존 기록 안내
   - 고객지원 연락처와 사업자 정보
4. 동의한 약관 버전·시각을 DB에 기록하고, 변경 이력도 남깁니다.

### 주의

사업자등록, 통신판매업 신고, 전자상거래·개인정보 보존 의무는 실제 판매 방식과 사업 형태에 따라 달라집니다. 공정거래위원회는 통신판매 관련 신고 및 사업자 정보 확인 경로를 안내하고 있으며, 정확한 적용 여부는 세무사·행정사·법률 전문가와 최종 확인합니다. [공정거래위원회 통신판매사업자 정보](https://www.ftc.go.kr/www/selectBizCommList.do?key=254), [통신판매 신고 FAQ](https://www.ftc.go.kr/www/selectExmplView.do?dscsnExmplSn=785&key=330&pageIndex=1&pageUnit=10&searchCnd=all)

## 3. 요금제와 PG를 함께 설계하기 — P0

### 먼저 정할 것

- 무료 / Like / More Like / Love 플랜별 텍스트·음성 한도
- 월간·연간 가격, 무료 체험 여부
- 환불·해지 시점과 다음 결제일 처리
- 사용량 초과 시 차단, 추가 결제, 다음 달까지 대기 중 어떤 정책인지
- API·TTS 원가를 제외하고도 플랜이 유지되는지

### PG 도입 순서

1. PG사를 비교하고 계약·심사에 필요한 사업자 정보를 준비합니다.
2. 테스트 결제로 결제 성공, 실패, 취소, 환불, 중복 결제를 모두 확인합니다.
3. PG 웹훅으로 결제 상태를 서버에서 검증합니다. 화면에서 “결제됨”이라고 보이는 것만 믿으면 안 됩니다.
4. 결제·구독 상태 변경은 감사 로그와 함께 DB에 남깁니다.

> PG는 가격표가 완전히 확정된 뒤에만 시작하는 일이 아닙니다. **사업자·정책·플랜 한도 초안**이 나오면 PG 심사 준비를 병행합니다.

## 4. 운영 서버와 배포 구조 정리 — P0

### 권장 구조

- 웹/API: 현재 Vercel 같은 관리형 배포 환경
- 웹 DB: Neon PostgreSQL
- Discord 봇·음성 처리: 24시간 실행되는 별도 워커/서버
- 파일·백업·로그: 운영 환경과 분리해 보관

### 서버를 바로 사기 전에 확인할 것

- 동시 음성 사용자 수
- 음성 처리 중 CPU·메모리·네트워크 사용량
- 월별 서버비와 장애 대응 난이도

초기에는 관리형 워커로 시작해 실제 부하와 비용을 측정한 뒤 전용 VM/서버로 옮기는 편이 안전합니다. 중요한 것은 “비싼 서버”보다 **자동 재시작, 로그 확인, 백업, 배포 롤백**입니다.

## 5. API 비용 측정과 한도 제어 — P0

### 반드시 기록할 값

- 사용자 ID, Discord 사용자 ID, 플랜, 캐릭터 ID
- 요청 종류: 텍스트 / STT / TTS / LLM / 임베딩
- 모델명, 입력·출력 토큰, 음성 초, 실제 비용, 요청 결과
- 일·월 단위 사용량과 오류율

### 제어 장치

- 사용자별·플랜별 월 한도
- 사용자별 짧은 시간 요청 제한
- 비용 급증 알림과 자동 차단 한도
- 재시도 횟수 제한 및 중복 요청 방지 키
- 관리자만 볼 수 있는 사용량·비용 대시보드

이 항목은 “API를 얼마나 빌려 썼는지”뿐 아니라, 어떤 플랜이 손해인지 판단하는 근거가 됩니다.

## 6. 보안·개인정보 점검 — P0

### 최소 점검 목록

- [ ] API 키, DB 비밀번호, `BOT_SECRET_KEY`는 코드·Git·브라우저에 노출되지 않는다.
- [ ] Vercel·Neon·Discord·Google OAuth 환경변수가 운영/개발 환경별로 분리되어 있다.
- [ ] 봇 API는 비밀키와 권한 검증을 모두 거친다.
- [ ] 사용자 A가 사용자 B의 기억·설정·결제 정보를 읽거나 수정할 수 없다.
- [ ] Discord ID ↔ 웹 사용자 ID 연결을 서버에서 검증한다.
- [ ] 음성 처리·장기기억 동의 여부를 API가 DB에서 확인하고, 변경·삭제 시 즉시 반영한다.
- [ ] 회원 탈퇴 시 삭제 대상과 법정 보관 대상이 분리되어 있다.
- [ ] DB 백업과 실제 복구 테스트를 수행했다.
- [ ] 오류 로그에 대화 본문, 토큰, 비밀번호, 결제 정보가 과도하게 남지 않는다.
- [ ] 의존성 취약점 검사와 권한 검토를 한다.

KISA의 소프트웨어 개발 보안 가이드와 웹 취약점 점검 지원 자료를 기준으로 정기 점검표를 운영하는 것을 권장합니다. [KISA 소프트웨어 개발 보안 가이드](https://www.kisa.or.kr/2060204/form?postSeq=5), [KISA 웹 취약점 점검 지원](https://www.kisa.or.kr/1020902)

## 7. 무작위 크롤링·악용 방지 — P0

### 해야 할 일

- `robots.txt`, `sitemap.xml`, 검색엔진 메타 태그를 추가합니다.
- 로그인·결제·봇 API에는 인증과 요청 제한(rate limit)을 적용합니다.
- 비정상 트래픽은 WAF/CDN에서 우선 제한합니다.
- 가입·문의·비밀번호 없는 공개 폼에는 CAPTCHA/Turnstile을 검토합니다.
- 관리자 API는 일반 사용자 화면과 분리하고 관리자 권한(RBAC)을 적용합니다.

### 중요한 구분

`robots.txt`는 검색 엔진에게 “어디를 수집하지 말아 달라”는 안내입니다. 공격자·스크래퍼를 막으려면 인증, WAF, 요청 제한, 봇 탐지, 서버 로그 분석이 필요합니다.

## 8. 관리자 운영 도구 만들기 — P1

### 추천 기능

- 사용자 검색: 웹 사용자 ID, Discord 사용자 ID, 이메일
- Discord 연동 상태, 동의 상태, 플랜, 최근 오류 조회
- 사용자 제한: 경고 / 임시 차단 / 영구 차단 / 해제
- API·TTS 사용량 및 비용 조회
- 결제 상태와 웹훅 처리 이력 조회
- 운영 메모와 모든 관리자 변경의 감사 로그
- 신고 접수, 이의 제기, 처리 상태

IP 차단은 보조 수단으로만 사용합니다. 학교·회사·모바일망에서는 여러 사람이 같은 IP를 쓰고, VPN으로 우회할 수도 있습니다. 기본 기준은 **웹 계정 + Discord 사용자 ID**이며, IP는 WAF에서 시간 제한 방식으로 함께 활용합니다.

## 9. 음성 품질: 기계음·끊김 완화 — P1

### 확인할 항목

- TTS 음성 샘플레이트·채널·볼륨을 Discord 재생 설정과 일치시킵니다.
- 오디오 조각을 이어 붙일 때 겹침·무음·클리핑이 없는지 테스트합니다.
- 재생 실패와 생성 실패를 분리해 기록합니다.
- 음성별 만족도와 오류율을 기록해 기본 음성을 선택합니다.
- 음성 처리 동의 불러오기 실패, Discord 계정 연결 실패를 명확한 오류 코드로 구분합니다.

실제 Discord 환경에서 짧은 문장, 긴 문장, 빠른 연속 발화, 여러 사용자 동시 접속을 모두 테스트해야 합니다.

## 10. 가입 후 튜토리얼·대시보드 만들기 — P1

대시보드 첫 화면은 정보만 보여 주기보다, 사용자가 바로 다음 행동을 할 수 있어야 합니다.

### 첫 사용 체크리스트

1. Google 로그인
2. Discord 계정 연결
3. 봇을 서버에 초대
4. 음성 데이터 처리 동의 확인
5. 캐릭터 선택 및 대화 방식 설정
6. Discord에서 첫 텍스트/음성 대화 시작
7. 장기기억 켜기·끄기와 삭제 방법 확인

각 단계는 완료 상태, 설명, 행동 버튼 하나를 함께 보여 줍니다. 막힌 단계에는 “왜 필요한지”와 해결 버튼을 제공합니다.

## 11. 일본어 지원 — P2

한국어 서비스 흐름과 약관·결제·오류 문구가 안정된 다음 진행합니다.

- 화면 문구를 코드에서 분리해 다국어 키로 관리
- 일본어 번역, 날짜·통화·시간대 형식 검토
- 캐릭터 말투와 TTS 품질 별도 테스트
- 일본 사용자용 약관·개인정보 고지는 현지 법률 검토 후 제공
- 고객지원 범위와 응답 언어를 명확히 고지

## 12. 출시 직전 리허설 — P0

실제 출시 전, 새 테스트 계정으로 아래 흐름을 처음부터 끝까지 통과합니다.

1. 가입 → 약관 동의 → 대시보드
2. Discord 연결 → 봇 초대 → 텍스트 대화
3. 음성 동의 → 음성 대화 → 음성 재생
4. 장기기억 저장 → 조회 → 삭제
5. 플랜 결제 → 웹훅 반영 → 한도 적용
6. 결제 취소·환불·실패·중복 결제
7. 로그아웃 상태의 페이지 권한 처리
8. 회원 탈퇴 → 삭제·보존 정책 확인
9. 봇/웹/DB 장애 후 재시작과 복구

하나라도 수동으로 고쳐야 통과하는 흐름이 있다면 유료 공개 전에 보완합니다.

# “웹개발자 등록”이 의미하는 것

법적으로 별도 “웹개발자 등록”이 필요한 경우를 말하는 것인지, 각 서비스의 개발자 콘솔 등록을 말하는 것인지 구분해야 합니다. Voice With AI에 실무적으로 필요한 것은 보통 아래 계정·설정입니다.

- Google Cloud Console: Google 로그인 OAuth 동의 화면·리디렉션 도메인 등록
- Discord Developer Portal: 봇, OAuth, 권한, 리디렉션 주소 등록
- Vercel: 배포·도메인·환경변수
- Neon: 운영 DB·역할·백업·접속 권한
- PG 개발자센터: 상점 ID, 웹훅, 테스트/운영 키

이들은 서비스 출시를 위한 기술 등록입니다. 사업자등록·통신판매 관련 절차와는 별도입니다.
